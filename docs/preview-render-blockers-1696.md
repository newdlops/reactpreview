# 부분 차단과 Query 데이터 조기 접근 수정 · 0.1.1696

## 수정 범위

VCM `InvestorInfoSection`은 본문이 보여도 소스가 요구하는 `VcmCompanyApp`이 빠져
`partial-blocked`였습니다. 팩토리 콜백의 `pageRoutes.filter(...)` 별칭과 중첩 `Route` 아래
슬롯을 인식하지 못해 바깥 소유자 복원이 생략됐습니다. 콜백 안에서 앞서 선언된 const 별칭과
요소 정체성을 유지하는 filter만 추적합니다. map·let·변수 가림·사용되지 않는 JSX를 슬롯으로
인정하지 않으며, 프로젝트 팩토리나 필터를 확장 호스트에서 실행하지 않습니다.

UDT `DetailBottomSheetContent`의 상위 `PosterCardScrollBox`는 실제 Query가 pending이고
data가 undefined인데 로딩 분기가 자동으로 건너뛰어져 `.length`에서 실패했습니다. 같은
결과의 상태와 data를 const 별칭·구조 분해로 연결하고, 이후의 직접 역참조가 확인된 경우에만
기존 `requiresAuthoredState` 계약을 적용합니다. Query 반환 객체·요청 수명 주기·실제 데이터는
유지합니다. 무관한 상태 플래그·다른 Query·기본값·선택적 접근은 새 근거로 인정하지 않습니다.

이 오류를 고친 뒤에는 자동 탐색이 선택한 상세 화면과 무관한 빈 Sheet를 열어 이미 렌더링된
내용을 가리는 문제가 드러났습니다. 컴파일러가 `overlay-sibling` 배치를 증명한 대상에서는
다른 소스의 오버레이를 자동으로 열지 않고, 이전 자동 열기도 복원 시 제거합니다. 수동 제어,
원래 앱 상태에 따른 열기, 같은 소스의 대상, 일반·deferred 배치와 기존 유한 경로 탐색은
그대로 유지합니다. 필수 소유자·실제 출력·선택 발생 위치의 성공 판정은 완화하지 않았습니다.

## 검증 방법과 한계

이전 0.1.1695와 수정 워커를 같은 보존 입력으로 비교했습니다. 원본 프로젝트는 읽기 전용이며
설정·패키지 스크립트·개발 서버를 실행하지 않았습니다. 실제 Chromium은 CDP 파이프와 차단된
외부 네트워크 아래에서 제품의 호스트 선택·재시도·HMR 프로토콜로 렌더링했습니다. 새 로컬
포트나 상주 서비스는 만들지 않았습니다.

VCM은 수정 후 추가 실행 경로 재시도 없이 ready가 됐고 바깥 그룹 페이지·레이아웃과 본문이
함께 표시됐습니다. UDT는 undefined.length 오류 없이 상세 본문이 표시되고 ready에 도달했습니다.
기존 UDT 동일 파일의 8회 경로 전환도 원래 장면과 ready를 유지했습니다. 390×844,
768×1024, 1440×900에서 생성된 화면과 CSS를 별도로 확인했습니다.

같은 상세 파일의 다섯 호출 경로(캐러셀, 세 PosterCardScrollBox 발생 위치, 그리드)와 캐러셀
복귀도 제품 companion 선택 UI로 전환해 6회 모두 본문과 ready를 확인했습니다. Tax 화면도
ready를 유지했습니다. Query pending·성공·오류와 수동·자동 분기 제어는 생성된 제품 런타임을
사용한 회귀 검사로 검증했으며, 원본 화면의 모든 개별 모달 열기·닫기를 직접 조작한 것은 아닙니다.

헤드리스 기본 수집의 6초 상한은 진행 중 상태도 partial-blocked로 기록할 수 있어, 별도 검증
하네스에서 경로별 유한 대기로 안정화를 관찰했습니다. 제품 타임아웃은 바꾸지 않았습니다.
외부 미디어·폰트·인증 서비스의 실제 접속 성공은 검증 범위가 아니며, 외부 미디어 차단으로
빈 이미지 또는 미디어 프레임이 보일 수 있습니다. 네이티브 VS Code 창 재로드와 사용자 작업창의
실제 화면 검증은 별도입니다.

자동 탐색은 여러 호출 경로와 viewer 상태를 계속 확인하므로 첫 본문 표시 이후에도 시간이
들 수 있습니다. 이번 변경만으로 모든 프로젝트의 전체 준비 시간이 줄었다고 주장하지 않습니다.
