# 0.1.1694: 렌더 그래프의 반복 구문 작업 축소

`createElement` 인수의 참조를 판정할 때 각 식별자마다 인수 구문을 다시 순회했다. 기존 부모
순회에서 확인한 직접 자식이 인수 목록에 속하는지만 비교한다. 하위 구문 재순회를 제거하며
callee·타입 인수·깊은 props·중첩 호출의 기존 구분과 첫 호출에서 멈추는 규칙은 유지한다.

JSX 요소의 자체 라벨과 Route element 라벨은 한 번의 동기 모듈 분석 안에서만 재사용한다.
전체 조상 경로·소유자·경로 해석·라우트 판단은 저장하지 않는다. 임시 목록은 반환 전에
해제 가능해지며 구문 트리를 반환 데이터나 상주 캐시에 추가하지 않는다. 같은 트리를 다시
분석해도 목록을 새로 만든다. 일반 태그는 기존 ASCII 이름 규칙으로 확실히 제외할 수 있는
경우에만 먼저 걸러 원문 읽기와 빈 목록 생성을 생략한다. 기존 원문 판정은 그대로 남는다.

사전 검사에서 공유 JSX 라벨 읽기 83회와 120개 참조의 구문 방문 23,360회를 재현했다.
변경 후에는 각각 6회 이하와 3,096회 미만의 작업량 검사를 통과했다. 일반 HTML 조상 태그의
원문 읽기는 0회다. 라우트 요소의 순서·인접 중복 제거·편집·callee 구분과 CSS 선택자 제외를
포함한 렌더 그래프 검사 83개가 통과했다. 이는 해당 합성 입력의 구문 작업량이다.

기존 소스 바이트를 보존한 비교에서 합성 소스 660개와 실제 소스 200개의 전체 그래프 결과가
같았다. 일반·한정·네임스페이스·비 ASCII·이스케이프 태그도 비교했다. 공유 트리를 세 번
분석하면서 47개 노드의 부모·위치·키 목록이 유지되는지 확인했다. 사용자 소스는 실행하지 않았다.

초기 SDK는 큰 페이지의 실제 준비 시간과 CPU 변화가 섞였다. 해당 6회 측정은 따로 보존하고,
일반 태그의 불필요한 작업까지 줄인 최종 SDK를 별도 새 워커에서 다시 비교한다. 서로 다른
SDK의 수치를 한 평균으로 합치지 않는다. 시간 비교에는 프로파일링 실행을 포함하지 않는다.
입력·의존 경로·CSS·컨텍스트·진단과 기존 탐색·메모리·120초 단계 정책을 함께 검증한다.

최종 안은 Tax 두 쌍과 UDT 두 쌍, 총 8회가 모두 완료했다. UDT 첫 쌍이 느려 반대 순서의
확인 한 쌍을 먼저 선언한 뒤 추가했다. 느린 표본도 평균에 포함하고, 초기 SDK의 6회는 따로
보관했다. 모든 비교에서 의존 경로·CSS·컨텍스트·진단이 같았다.

| 최종 표본 평균 | 0.1.1693 | 0.1.1694 |
| -------------- | -------: | -------: |
| Tax 전체 준비  |  48.36초 |  30.66초 |
| Tax 번들링     |  32.18초 |  23.79초 |
| Tax Node CPU   |  63.40초 |  41.69초 |
| UDT 전체 준비  |   4.97초 |   7.28초 |
| UDT 번들링     |   3.80초 |   5.53초 |
| UDT Node CPU   |   7.43초 |   9.17초 |

초기 SDK 비교의 Tax 전체 평균은 15.15→15.36초, UDT는 2.53→2.15초였다. 실행 사이의
시간·CPU 변동이 크며 최종 결과도 방향이 다르다. OS 캐시를 비우지 않았고 외부 부하를 통제한
실험은 아니다. Tax의 큰 감소를 코드의 일반적 개선율로 주장하지 않는다. UDT에서는 느린
표본과 반대 순서 확인의 5.45→5.74초를 모두 남겼다. 전체 프리뷰 속도 개선은 아직 확정할 수
없으며, 이번 변경에서 확인한 효과는 반복 구문 작업 감소와 기존 그래프·화면 결과의 보존이다.
