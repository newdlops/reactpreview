# 대화형 네이티브 번들러 GC 기본값 검증

## 적용 범위

대화형 Node 4GiB 워커에서 호스트 메모리가 32GiB 이상이고 사용 가능한 CPU 슬롯이 8개 이상일 때
네이티브 기본값을 `GOMEMLIMIT=640MiB`, `GOGC=200`으로 선택한다. Go CPU 병렬도는 기존 2개다.
세 Go 환경 변수 중 하나라도 명시돼 있으면 기존 격리 함수의 결과를 그대로 사용한다.

경로 워커 384MiB와 인벤토리 워커 2GiB의 격리 정책 v3, Node heap, Sass 512MiB·30초,
15초 유휴 종료와 소스·그래프·타입 분석 한도는 유지한다. 시스템 설정이나 자동 실행 등록은 없다.

## 검증 방법

설치된 0.1.1674 컴파일러의 동일한 바이트를 양쪽에 사용하고 네이티브 환경 기본값만 비교했다.
32회 예비 검증 뒤 독립적인 네 파일·두 반복·네 준비 단계의 64회 확대 검증을 수행했다.
양쪽 모두 포트를 열지 않는 동일한 CDP 파이프 기반 브라우저 검증을 사용했다.

640MiB 후보를 측정하기 전에 IR 최초 표시와 초기·갱신 흐름의 최소 개선량, 다른 화면의
초기·갱신 흐름에서 허용하는 2% 변동 범위, 단계별 상한과 CPU·메모리 상한을 고정했다.
2%는 공학적 허용 범위이며 통계적 유의성 주장에 사용하지 않는다. 이전 후보의 결과와 타이밍은
합산하지 않았고, 모든 성공·실패 표본을 보존했다.

## 확대 검증 결과

| 고정 사례              | 초기 준비 시간 변화 | 새로고침 시간 변화 |
| ---------------------- | ------------------: | -----------------: |
| VCM 공통 Section       |               -1.2% |              -3.6% |
| Session 페이지         |               -6.2% |              -0.5% |
| VCM third 공통 Section |               -4.5% |              -1.7% |
| IR 페이지              |              -13.0% |             -15.6% |

IR 첫 fast 준비 완료 시간은 평균 약 1.47초, 11.6% 줄었다. 네 사례의 초기·갱신 전체 시간은 각각 약 6.3%,
5.6% 줄었고 Node와 자체 네이티브 자식의 관측 CPU 합계는 약 9.1% 줄었다.
관측된 Node·네이티브 합산 RSS 최고치는 약 3.37GiB로 사전 상한 3.5GiB 안이었다.
CPU 수치에는 브라우저가 포함되지 않으며 1초 간격 RSS 표본은 순간 최대치를 보장하지 않는다.

64회 모두 정상 마운트됐고 32개 비교 쌍의 CSS 해시·의존성·진단·화면 구성·문맥 범위·관찰
디렉터리가 일치했다. 모든 원본 프로젝트 쓰기 방지 기록은 0회였다.
이는 고정 사례의 기능·렌더링 검증이며 모든 프로젝트에 같은 개선율을 보장하지 않는다.

로컬 원본 결과는 `.tmp/preview-native-compact-gc-1674-20261023t2054z/native-full/comparison.json`과
인접한 준비 단계별 압축 기록에 보관한다. VS Code 작업창 재로드나 별도의 시각 검사 완료를
이 결과만으로 주장하지 않는다.

## 현재 환경의 전체 검사 제한

`npm run check`는 5,338개 테스트 통과·10개 실패로 끝났다. 실패는 현재 호스트에 전용 주소
`127.1.0.1`이 없어 기존 HTTP 브라우저 검사가 바인딩하지 못한 경우다. 같은 주소 오류는
이 변경 전 0.1.1674 검증 기록에도 있으며 해당 렌더러·검사 파일은 이번에 수정하지 않았다.
타입·린트·형식 검사, 워커 회귀 검사 85개와 위의 포트 없는 실제 페이지 검증은 통과했다.
전체 검사 통과로 보고하지 않으며 시스템 루프백이나 보안 정책을 바꾸지 않는다.
