# 서버 쿼리 변환의 범위 확인과 복사 비용 감소 — 0.1.1703

서버 계약 import와 이름이 같은 매개변수·지역 변수를 구분하지 않으면, 원래 함수가
반환한 데이터를 서버 계약용 표본으로 덮어쓸 수 있었습니다. 이제 기존 타입 프로그램의
검사기로 호출 수신자의 실제 import 선언을 확인합니다. 새 프로그램이나 파일 조회를
추가하지 않으며, 근거가 없으면 원본 호출을 유지합니다.

## 변경

- default·named·alias·namespace import의 실제 참조만 타입 기반 서버 쿼리 변환을 받습니다.
  매개변수, 구조 분해, var 호이스팅, 블록·catch·loop·switch 및 이름 있는 함수·클래스
  표현식의 지역 이름은 해당 함수의 결과를 유지합니다. type-only import도 제외합니다.
- 관련 쿼리 모양의 호출만 문자열로 집계합니다. 같은 텍스트의 지역 호출도 순서에는
  포함하여 타입 프로그램의 호출 위치와 어긋나지 않게 합니다.
- 기존의 모듈당 성공한 변환 64개 한도에 도달하면 탐색을 종료합니다. 타입을 알 수 없어
  변환하지 않은 호출은 이 한도를 소모하지 않습니다.
- 삽입 위치를 역순으로 모아 원문 구간을 한 번에 합칩니다. 수정마다 모듈 전체를 다시
  복사하던 비용을 줄이고 중첩 호출의 평가 순서와 실행 횟수를 유지합니다.

## 제한된 변환 측정

이전·현재 변환기를 같은 Node 프로세스에서 교대로 실행했습니다. 각 사례는 예열 4회 뒤
12회씩 측정했으며, 모든 출력 문자열과 타입 질의 횟수가 기존과 같았습니다. 이 실험의
oracle은 고정된 기술용 표본을 반환하므로 실제 타입 분석·파일 준비 비용을 포함하지 않습니다.

| 사례                                      | 이전 중앙값 | 현재 중앙값 | 확인한 연산 변화         |
| ----------------------------------------- | ----------: | ----------: | ------------------------ |
| 무관한 호출 3,000개 + 쿼리 1개, 약 91KB   |      6.61ms |      6.59ms | 호출 문자열 3,001 → 1    |
| 쿼리 64개 뒤 무관한 호출 3,000개, 약 93KB |      8.23ms |      5.12ms | 방문 노드 21,648 → 643   |
| 큰 문자열을 포함한 쿼리 64개, 약 412KB    |      9.41ms |      1.32ms | 전체 원문 반복 복사 제거 |
| 중첩 쿼리 3개                             |     0.023ms |     0.022ms | 결과·평가 순서 유지      |

## 실제 프로젝트 검사

검색 페이지와 VCM을 각각 이전·현재 컴파일러로 최초·재준비하여 총 8회 비교했습니다.
진단 계측은 검증 전용 번들에만 넣었고 설치 번들에는 포함하지 않습니다.

- 검색 페이지: 호출 문자열 집계 774 → 290. 쿼리 290개의 전체 표본 값과 호출 순서가
  최초·재준비 모두 일치했습니다. 의존성 3,845개와 전체 CSS도 일치했습니다.
- VCM: 이 서버 쿼리 변환의 적용 대상이 없었으며 기존 문맥·의존성 2,130개·전체 CSS를
  유지했습니다. 두 프로젝트 모두 새 오류·경고 종류가 없습니다.
- 검색 최초 준비 6.83 → 7.27초, 재준비 4.95 → 5.42초, VCM 최초 준비
  6.19 → 5.54초, 재준비 3.91 → 3.86초였습니다. 계측과 실행 부하가 포함된 단일 쌍의
  수치이며, 전체 프리뷰가 빨라졌다고 주장하지 않습니다.
- 원본 프로젝트 쓰기는 차단하고 검증 워커·esbuild 자식의 종료를 확인했습니다.

영구 회귀검사는 실제 타입 검사기에서 import 형태·지역 변수 가림·미해석 타입을 검사하고,
생성 JavaScript를 실행하여 원래 지역 결과와 중첩 쿼리의 실행 횟수를 확인합니다.
전체 검사와 production 패키지·설치 일치 확인은 해당 버전의 검증 기록에 보관합니다.

원본 CSS, 테마·인증·Provider·라우터, 후속 경로 탐색, 타입 프로그램의 메모리 상한,
단계 제한은 변경하지 않습니다. 원시 JavaScript 청크 이름의 바이트 일치나 네이티브 창의
시각 검증은 이 검사로 확인한 사항이 아닙니다.
