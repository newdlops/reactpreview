# 복구 사전학습 v2 — 0.1.1516

기존 후보의 순위를 학습하는 소형 MLP를 개선했습니다. 임의 코드를 이해해 새로운 복구 코드를
생성하는 LLM은 아닙니다. [v1 기록](neural-pretraining.md)은 별도로 보존합니다.

## 달라진 판단

- 입력 144칸: 제한된 의미 토큰 96칸, 기존 수치 32칸, 원인·이력·비용 수치 16칸.
- 실제 required-path 파서에서 배열·호출·문자열·수치 연산 요구를 집계합니다. 중첩 throw와
  컴파일러가 증명한 scalar guard 개수도 입력하지만 오류 원문이나 실제 값을 넣지 않습니다.
- 기존 라우터 소유 여부, 정해진 route evidence enum, wrapper 종류를 구분합니다.
- 검증된 실패 수와 남은 후보 수는 별도 `recoveryContext`로 전달합니다. 온라인 v4 입력·문맥
  해시·170개 온라인 파라미터·192개 익명 기록은 변경하거나 초기화하지 않습니다.
- 같은 문맥에 성공 또는 불확실한 시도 기록이 있으면 사전 모델은 양보합니다. 실패만 있다면
  실패·제외 후보를 다시 고르지 않고 미시도 대안이 둘 이상 남았을 때 비교를 계속합니다.
- Page Execution의 전환 요청 횟수가 아니라 `outcomeByExecutionCandidateId`의 실제 실패만
  전달합니다. 요청했거나 대기 중인 후보를 검증된 실패로 바꾸지 않습니다.

## 비용 학습과 안전 경계

학습 목적은 비용 가중 이진 교차 엔트로피와 후보 쌍 간 순위 손실입니다. 실패 시 비용 가중치는
`1 + min(2, cost / 25)`이며 후보 간 logistic 손실 비중은 0.15입니다. 같은 문제에서 실제 성공한
후보를 실패보다 앞세우고, 둘 다 성공한 경우에는 비용 차이가 있는 쌍에 최대 0.2의 낮은 가중치를 줍니다.

비용은 **밀리초가 아닌 구조적 작업량 추정치**입니다. 페이지 경로의 깊이·wrapper·조건 개수,
페이지 실행의 owner 깊이·mount 개수, 예외 복구의 중첩·필수 경로 개수로 1~50 단위를 계산합니다.
렌더 벤치마크 시간을 성공 확률처럼 학습했다고 주장하지 않습니다.

런타임은 모델 점수에서 `min(0.075, cost * 0.0015)`만 차감합니다. 최고 후보의 원점수 0.8 이상과
차순위 대비 원점수 격차 0.2 이상이거나, 상위 두 후보 원점수가 모두 0.9 이상이고 차감 후 격차가
0.02 이상일 때만 관여합니다. 이 수치는 보정된 성공 확률이 아닙니다. 약한 예측을 비용만으로
확신으로 바꾸지 않습니다. 일반 온라인 경험 혼합, 수동 선택·정지·분기 유지·반복 예산·rollback과
실제 목표 출력의 연속 검증은 그대로입니다.

미지원·혼합 후보, 학습 수치 범위 밖, 손상된 형식/차원/체크섬에서는 기존 정책으로 돌아갑니다.
최대 12개 후보와 64개 익명 벡터 캐시를 유지하며 가중치는 필요할 때만 디코딩합니다.

## 데이터와 실제 실행

저장소 소유 SSR 재현과 격리된 Chromium 실험을 사용했습니다. 사용자 소스·프로필·실패 로그를
수집하거나 업로드하지 않았습니다. 학습에 사용한 React 실험은 확장에 포함하지 않으며,
효과 의존성을 제한하고 실험 모듈을 개발 작업에서만 로딩하도록 구성했습니다.

| 구분      | 최초 사례 | 관측 실패 뒤 재시도 상태 | 학습/평가 입력·결과 쌍 |
| --------- | --------: | -----------------------: | ---------------------: |
| 학습      |    36,160 |                    6,737 |                136,577 |
| 검증      |     9,040 |                    1,734 |                 34,290 |
| 최종 평가 |     9,040 |                    1,697 |                 34,275 |

재시도 상태는 이미 실행해 실패가 확인된 선행 후보만 제거해서 만듭니다. 이후 후보의 결과를
특징에 넣지 않습니다. 결과를 이력이 다른 상태에서 재사용하므로 136,577개가 모두 독립적으로
수집한 실제 프로젝트 오류라는 뜻은 아닙니다. 학습 특징 벡터는 44,643종입니다.

Chromium에서 별도로 240개 사례·720개 후보를 실행했습니다(학습 480, 검증 120, 평가 120 후보).
학습은 비동기 effect, 검증은 Lazy/Suspense, 평가는 지연된 출력 재발을 사용합니다. 초기 상태가
가라앉은 뒤 세 프레임 연속으로 목표 마커가 있고 `?`와 예외가 없어야 성공입니다.
성공 240·실패 480·예외 240개였고 외부 리소스 요청과 CSP 위반은 0개였습니다.
이 프레임 기반 학습 실험은 제품의 기존 시간 기반 성공 검증기를 대체하지 않습니다.

SSR의 신규 경로 실험도 root route, outlet map, nested router로 구현을 나누고 provider 값도
배열·Set·객체로 분리했습니다. 그러나 모두 저장소 소유의 제한된 생성 실험입니다.
구분 간 동일 특징 벡터는 0개지만 **독립적인 실제 사용자 프로젝트 평가가 아닙니다.**
