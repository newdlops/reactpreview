# 자동 라우트와 호출 경로 정렬 — 0.1.1678

선택한 공유 컴포넌트가 여러 페이지에서 사용될 때, 라우트 카탈로그의 첫 페이지와 실제
렌더링 후보의 첫 페이지가 달라질 수 있었다. 실제 RTCC 입력의 `HeavyTaxEditModal`에서는
상세 페이지를 경유하는 호출 경로에 수정 페이지의 URL이 붙었다. 수정 페이지는 공유 폼을
`variant="edit"`로 사용하므로 해당 경로를 기대한 데이터 보완으로 해결할 수 없었다.

## 변경

- 이미 수집한 후보에 라우트 증거를 적용해 실제 페이지 후보의 우선순위를 계산한다.
- 자동 라우트 선택은 그 후보의 동일한 소스 경로와 컴포넌트 식별자를 함께 확인한다.
  호출 경로에서 대상에 더 가까운 페이지를 상위 애플리케이션의 짧은 경로보다 우선한다.
- 현재 요청이 소유한 렌더링 경로만 인정한다. 같은 이름의 다른 파일이나 외부에서 만든
  경로 객체는 우선 근거로 사용하지 않는다.
- 기존 요청 범위의 라우트 분석 provider를 사용해 루트 분석을 한 번만 수행하고 `finally`에서
  해제한다. 별도 서비스, 전역 캐시, 새 의존성, 탐색 범위 확대는 없다.
- 명시적 라우트 선택은 기존 절차를 따른다. 다른 호출 경로와 라우트 목록도 유지한다.
- 명시적 라우트 소유자가 없는 문맥 선택에서만 호출 경로를 우선한다. 지연 로딩·재수출 모듈도
  같은 호출 경로를 유지한다. 중첩 Provider가 직접 소유한 페이지의 기본 선택과 선택하지 않은
  페이지의 번들 제외는 기존 절차를 유지한다.

기존 스타일 수집, Provider·Router, 가드 복구 정책과 자원 한도는 변경하지 않았다.
스타일 결과는 실제 화면에서 따로 검증했다.

## 회귀 검사

기존 코드에서 실제 상세 페이지를 선택해야 하는 검사가 `EditPage`를 반환하며 실패했다.
문맥만 제공하는 중간 모듈, 같은 이름의 다른 파일, 중첩 Provider의 기본 페이지, lazy·재수출,
같은 모듈의 서로 다른 export, 수동 선택을 포함한 관련 60개 검사가 최종 코드에서 통과했다.

`npm run check`는 5,423개 통과·10개 실패다. 실패 10개는 이전 0.1.1677 검사와 정확히 같은
항목이며, 환경의 `127.1.0.1` 바인딩 오류가 남아 전체 통과로 표현하지 않는다. 줄 수·타입·lint·
format 검사는 통과했다. 실제 화면 검증은 TCP 포트를 열지 않는 CDP pipe와 Fetch interception으로
수행했다. 시스템의 주소·권한·보안·VPN 설정은 변경하지 않았다.

## 동일 입력 6개 비교

최종 SDK와 설치된 0.1.1677을 같은 읽기 전용 입력에서 순차 실행했다. 사례별 순서를 번갈아
배치했으며 다른 컴파일·전체 검사와 겹치지 않았다. 아래 시간은 초 단위이며 왼쪽이 이전 버전이다.

최초 준비 합계는 95.27 → 103.73초, 복구를 포함한 누적 합계는 179.76 → 180.66초다.
큰 모달의 개선으로 전체가 빨라졌다고 결론 내릴 수 없다. 사례당 한 쌍의 관측치이므로 p95나
모든 파일의 개선을 입증하지 않으며, 전체 최초 준비 속도는 이번 비교에서 약 9% 느리게 측정됐다.

관측한 Node·네이티브 합산 RSS 피크는 3,698.69 → 3,484.44MiB로 약 6% 줄었다.
사례별 합산 피크 변화는 약 -5.79%~+3.02%였으며 기존 자원 한도는 유지했다.

실제 정상 렌더링은 두 버전 모두 4/6이다. 정상 네 사례의 CSS 바이트는 동일했고 390×844,
768×1024, 1440×900에서 문서 가로 넘침 없이 스타일을 확인했다. 메뉴 열기·Escape 닫기,
라디오 이동·복원, 검색·숫자·확인 문구 입력과 Tab 이동을 실제 마우스·키보드로 검증했다.
저장·삭제를 제출하지 않았다. 실패한 두 사례를 포함해 최종 스크린샷 18개를 별도로 검토했다.

## 로컬 설치

Production prepublish build와 darwin-arm64 VSIX 검증 후 0.1.1678을 로컬에 재설치했다.
설치된 실행 파일 2,461개의 바이트가 검증한 패키지와 일치하고, 실제 화면에 사용한 SDK도 동일하다.
설정·학습 기록 9개 파일의 내용·권한을 보존했다. 원본 프로젝트 29,613개 파일과 읽기 전용
스냅샷의 내용·권한도 다시 확인했다. VS Code 작업창을 재로드했다고 가정하지 않는다.

## 남은 범위

올바른 URL을 선택하는 것과 페이지의 데이터 조건을 만족하는 것은 별개다. 최초 실제 실행에서
상세 페이지의 `data.meeting.isZuzuGenerated` 분기를 자동으로 진행한 뒤 런타임 오류가 발생해
기존 안전 복구가 그 선택을 되돌렸다. 이 상태와 이후 대체 출력은 완전한 렌더링 성공으로
계산하지 않는다. CDP 오류 이벤트에서 `Meeting must require either registration or resolution`을
확인했다. 상세 페이지의 단계 구성 helper에서 필요한 데이터 조건을 만족하지 못하는 경우다.
원래 데이터 조건이나 사용자 선택을 무조건 덮어쓰는 변경은 하지 않았다.

원래 목표인 렌더링·스타일 성공률과 컨텍스트 탐색·번들링 시간 개선은 계속 유지한다.
각 실제 입력의 실패와 자원 사용도 결과에 포함한다.
