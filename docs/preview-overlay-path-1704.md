# 경로 전환의 검증 소유권과 모달 기본값 보존 — 0.1.1704

이미 성공한 페이지를 유지한 채 다른 경로의 번들을 적용하면, 새 경로의 검증 결과가
도착하기 전에 이전 경로를 복원할 수 있었습니다. 같은 문서 안에서 교체되는 프리뷰는
과거 판정도 보관하므로, 두 경로가 모두 성공해도 반복 준비가 발생할 수 있었습니다.

## 경로 전환

- 새로 커밋된 경로와 소스 리비전을 기록하고 현재 실행의 판정까지 기다립니다.
  이전 경로의 늦은 판정이나 과거 성공 기록은 이 대기를 해제하지 않습니다.
- 일반적인 상태 갱신은 현재 검증된 경로를 유지합니다. 명시적인 추가 경로 탐색은 기존처럼
  더 적은 개입으로 성공한 실행 계약을 선택할 수 있습니다.
- 현재 실행의 성공·최종 실패가 확인되면 대기를 해제합니다. 실패 복구, 사용자의 수동 경로
  선택, 서로 다른 호출 경로 탐색과 기존 검사 한도는 유지합니다.
- 대기나 생략을 성공 판정으로 기록하지 않습니다. 새 경로와 새 소스 리비전은 다시 검증합니다.

VCM의 `vcm-pfc-list-page.tsx` 사용자 로그에는 두 후보가 같은 `/investor/pfc` 경로에서
성공한 뒤에도 번들이 반복 교체된 기록이 있었습니다. 저장된 학습 상태를 읽기 전용으로
복사한 실제 브라우저 검사에서 기존 버전은 후속 빌드 2회, 수정 후보는 1회 뒤 준비됐습니다.
두 후보를 각각 명시한 검사도 후속 빌드 없이 준비됐으며, 각 실행은 30초 이상 재빌드 요청
없이 출력과 전체 페이지 문맥을 유지했습니다. VCM 의존성 2,791개와 CSS도 같았습니다.
새 브라우저에서 무한 반복 자체는 재현되지 않았고, 같은 문서의 전환 경쟁 조건은 영구
회귀검사로 재현·검증했습니다. 이 관찰은 해당 파일과 상태에 대한 확인이며 모든 프로젝트에서
반복이 사라졌다는 보장은 아닙니다.

## 원본 모달 기본값

`ia-pf-company-create-modal.tsx`는 원본 공통 모달이 기본 크기 `medium`을 사용해야 하지만,
프리뷰가 선택 속성인 `size`에 숫자 `0`을 생성했습니다. 실제 대화상자의 최대 폭이 0으로
계산되어 제목과 입력창이 세로로 눌렸고, 배경만 화면 전체를 덮었습니다.

- 함수 본문의 구조 분해에 기본값이 있는 속성은 자동 필수 입력으로 승격하지 않습니다.
  기존 매개변수 구조 분해와 같은 규칙을 적용합니다.
- JSX에서 명시적으로 넘긴 선택 속성을 분석하더라도, 그 객체 안의 선택 필드를 모두
  필수로 취급하지 않습니다. 내부 선택 필드에는 별도의 원본 사용 근거가 필요합니다.
- 필수 형제 필드와 독립적인 직접 사용 근거는 보존합니다. 기본값 표현식을 분석 과정에서
  실행하지 않으며 원본 CSS·모달·포털·이벤트 구현도 수정하지 않습니다.

실제 브라우저에서 대화상자의 폭과 중앙 정렬을 확인했습니다. 390×844, 768×1024,
1440×900 화면을 각각 확인했고, 마우스로 회사명 입력창을 선택하여 문자열을 입력한 뒤
Tab으로 법인등록번호 입력창에 이동했습니다. 외부 서버로 폼을 제출하지 않았습니다.
화면의 데이터·검증 메시지는 프리뷰가 생성한 값이며 실제 업무 데이터 검사는 아닙니다.

VCM의 768px 화면에서는 기존·수정 버전 모두 원본의 넓은 레이아웃이 화면 오른쪽을
넘었습니다. 이번 검사는 해당 원본 반응형 제약을 유지한 상태에서 경로 준비와 지속 출력을
확인했습니다.

## 검증 범위

영구 회귀검사는 같은 문서의 새 경로, 과거 성공, 소스 리비전 교체, 현재 실패 복구,
늦은 이전 판정, 실행 경로 없는 초기 준비, 구조 분해 별칭과 모달 크기·이벤트 기본값을
포함합니다. 관련 11개 파일의 92개 검사를 통과했습니다. 전체 검사와 production VSIX 및
설치 파일 일치 여부는 이 버전의 검증 기록으로 확인합니다.

검증은 원본 프로젝트 쓰기를 차단하고 유한한 별도 워커·임시 브라우저에서 실행했습니다.
브라우저 제어에는 파이프를 사용해 TCP 포트를 열지 않았습니다. 사용 중인 VS Code 창의
재로드나 장시간 네이티브 프리뷰 검증을 완료한 것으로 간주하지 않습니다.
