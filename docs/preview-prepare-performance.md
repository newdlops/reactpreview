# 페이지 문맥 검증과 준비 비용: 0.1.1663

기존 앱의 커스텀 팩토리에 `() => import('./module').then(module => module.Page)`를
직접 전달하면, 이전 렌더 그래프는 선택된 export가 팩토리 결과로 전달되는 관계를 놓쳤다.
그 결과 실제 페이지 내용이 보여도 앱 진입점까지 연결되지 않아 페이지 문맥 검증이 남았다.

이제 직접 전달된 로더의 단일 return과 정확한 모듈 속성 선택을 조건부 `value-flow`로
기록한다. `React.lazy`라는 의미를 임의로 부여하지 않으며, namespace 반환·계산된 속성·
다른 객체의 속성·중첩 호출·효과가 있는 콜백은 계속 불명확한 근거로 남긴다.
기존 React/Next 지연 로딩 분석과 실제 페이지 루트·타깃의 마운트 및 출력 검증은 유지한다.

자동 준비는 동일 충실도의 후보를 모두 비교해 기존 정렬 기준으로 승자를 확정한다.
성공한 그룹보다 충실도가 낮은 후보는 선택 결과를 바꿀 수 없으므로 준비를 미룬다.
후보 목록과 신원은 보존하고 진단에는 `deferred-until-selected`를 기록한다.
사용자 또는 자동 복구가 해당 후보를 실제 선택하면 현재 소스에서 그 후보의 frontier를
다시 검증한다. 상위 후보가 모두 거부되면 다음 그룹을 검사하며, 전부 실패하면 기존의
가장 작은 거부 후보 진단을 유지한다.

자동 번들의 props 추론도 최종 선택된 실행 루트와 명시적으로 구성하는 형제에 적용한다.
실행하지 않는 복구 후보의 중첩 자식 props는 이후 선택 시점에 추론한다.
명시적 route execution artifact의 기존 준비 순서는 유지한다.

생성한 훅 대체 값의 React ref는 일반 불변 데이터와 구분한다. 실제 `@types/react`의
`RefObject`·`MutableRefObject` 선언에서만 전용 descriptor를 만들고, 마운트·분리 때
`current`를 쓸 수 있게 복원한다. 실제 훅이 반환한 ref 신원과 일반 데이터의 불변성은 유지한다.
메타데이터 속성이 있는 React 컴포넌트 타입도 일반 레코드로 만들지 않는다. React 선언으로
확인된 생성자만 기존의 `null` 렌더 함수 descriptor로 복원하며 실제 컴포넌트가 우선한다.

그래프·구문·소스·캐시 한도, 4 GiB 메인 워커, 한 개의 512 MiB 일회성 Sass 작업과
30초 제한, 1,250 ms 안정화 대기와 5,000 ms 상한을 변경하지 않는다.
시스템 자동 실행·별도 상주 서비스·보안 정책 변경은 사용하지 않는다.
원본 프로젝트를 실행하거나 수정하지 않고 고정 복사본과 이미 설치된 의존성만 읽는다.
로컬 서버는 전용 루프백 `127.1.0.1`에만 바인드하고 검사 후 종료한다.

검증에서는 로그에 남은 네 대상과 결과를 보기 전에 SHA-256 순서로 고정한 여섯 페이지를
비교한다. 실제 `preparing-runtime`부터 다음 `analyzing-project`까지의 시간과 전체 컴파일·
Chromium 안정화 시간을 함께 기록한다. 실패 대상을 표본에서 제외하지 않는다.
기능 검증과 별도로 실제 렌더링의 세 화면 크기·키보드·팝업·새로고침을 확인한다.

## 2026-10-20 고정 표본 비교

0.1.1662와 최종 0.1.1663 production worker를 동일한 열 개 입력에서 번갈아 실행했다.
매 실행마다 새 워커와 Chromium을 사용했으며 운영체제 파일 캐시는 초기화하지 않았다.
각 버전·대상 조합을 한 번씩 실행한 결과의 중앙값은 다음과 같다.

| 구간                        |     0.1.1662 |     0.1.1663 | 감소율 |
| --------------------------- | -----------: | -----------: | -----: |
| Prepare Preview             |  3,015.82 ms |    690.93 ms | 77.09% |
| 전체 컴파일                 | 13,558.80 ms | 11,363.94 ms | 16.19% |
| Chromium 확인까지 전체 대기 | 19,591.47 ms | 17,277.53 ms | 11.81% |

준비 시간은 열 개 중 여덟 개, 전체 대기는 아홉 개에서 줄었다. 모든 파일에서 같은 개선을
보장하는 수치는 아니다. 이전 버전은 정상 네 개, 연결 미확인 세 개, 렌더 실패 두 개,
프로토콜 실패 한 개였으며, 새 버전은 열 개 모두 타깃 마운트·출력과 정상 종료를 확인했다.
실패한 실행의 종료 시간도 기록에 포함했고 비교 대상에서 제외하지 않았다.
원시 입력 신원·개별 결과·정리 기록은 작업 검증 디렉터리에 보존한다.

그 다음 버전의 타입 준비·선언 탐색 변경은 [전체 대기 최적화](preview-total-wait-performance.md)에 기록한다.
