# 준비 대기를 중단시키는 타이머 충돌 수정: 0.1.1664

Inspector는 하이라이트 예약에 사용한 취소 API를 함께 보관한다. 애니메이션 프레임과
일반 타이머는 번호 공간이 달라 같은 번호가 생길 수 있다. 프레임 정리에서 `clearTimeout`을
함께 호출하면 다른 소유자의 준비 확인·비동기 작업을 취소한다. 실제 실패의 타이머와 호출
스택으로 확인했고, 같은 번호의 무관한 타이머를 보존하는 회귀 검사로 방지한다.

타입 계산 시점·구문 색인·선언 파싱의 추가 최적화는 고정된 열 개 입력의 전체 대기를
일관되게 줄이지 못해 되돌렸다. 실험 소스와 모든 비교 결과는 프로젝트 내부 진단 기록에
보존한다. 일반 컴파일의 평균·중앙값 속도가 향상됐다고 주장하지 않는다.

최종 런타임 변경은 위 스케줄러 파일 하나다. 같은 번호의 무관한 타이머가 살아 있어야 하는
회귀 검사, 실제 Chromium의 충돌 재현, 고정 입력의 실제 타깃 마운트·출력과 연속 빌드를
확인한다. 기능 검사와 실제 세 화면 크기의 스타일·팝업·캐시된 모듈 새로고침 검사는 분리한다.

검증 브라우저는 제품 실행 경로처럼 시작 탭에 연결하고, 실제 revision과 content hash가
포함된 진입 URL을 사용한다. 임의의 가짜 artifact hash나 revision 없는 진입 URL로
반복 새로고침을 검증하지 않는다. 모든 검증 서버는 `127.1.0.1`에서 한정된 실행 뒤 종료한다.

4 GiB 메인 워커·512 MiB 일회성 Sass 작업 한 개·30초 제한과 기존 유휴 종료를 유지한다.
1,250 ms 안정화 대기와 5,000 ms 상한도 유지한다. 프로젝트 설정·스크립트는 실행하지 않고
고정된 읽기 전용 입력과 설치된 의존성을 사용한다. 별도 서비스나 시스템 자동 실행을 만들지 않는다.
