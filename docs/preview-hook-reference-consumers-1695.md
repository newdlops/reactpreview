# 0.1.1695: 훅 보조 검사의 반복 구문 탐색 축소

직접 호출·Promise 결과·오버레이 상태·배열 길이·대상 조기 반환 검사가 같은 함수 본문을
반복 순회했다. 주 분석기가 이미 만든 식별자 인덱스가 있으면 정확한 이름을 포함하는 구문과
그 조상만 방문한다. 인덱스가 없으면 원래 전체 순회를 수행하며, 보조 검사 때문에 새로운
인덱스나 구문 트리를 보관하지 않는다. 조회 이름은 검사 생성 시점에 고정한다.

각 소비자의 중첩 함수·가려진 변수·조건 판단·방문 순서는 유지한다. 인덱스에는 구문상의
이름 위치만 있고 대체 값이나 선택한 화면의 판단 결과는 없다. 같은 트리에서 선택 대상을
바꾸거나 같은 파일을 편집해 새 트리를 만들면 현재 선택과 구문으로 다시 판단한다.
원래 소스·Provider·라우터·CSS·생성 데이터의 한도와 120초 단계 정책은 변경하지 않는다.

캡처된 Promise 호출, 가려진 callable, 조건부 오버레이, 캡처된 배열 길이와 다중 인수 Array,
같은 트리의 대상 변경·편집을 검사한다. 단독 보조 검사는 관련 없는 배열의 자식을 한 번만
읽으며, 이미 인덱싱한 트리의 반복 검사에서는 그 배열을 읽지 않는다. 실제 도달 소스와 UDT
소스 1,292개의 전체 훅 변환 999개가 기존 구현과 같다. 추가 감시 경로 148개는 실제 파일이
없는 선택적 경로여서 별도 기록했고 비교 성공에 포함하지 않았다. 사용자 소스는 실행하지 않았다.

VCM InvestorInfoSection의 현재 설치본 CPU 프로파일은 약 9초 준비 중 타입 프로그램·파일
경로 조회·훅 분석 비용을 확인하는 데 사용했다. 프로파일링 표본은 시간 비교에서 제외한다.
최초 진단은 컴파일 뒤 자원 보고 함수명 오류로 종료했다. 실제 컴파일 결과와 읽기 전용 보호
기록은 남았고, 이후 비교 하네스는 올바른 종료 함수를 사용한다.

초기 구현은 보조 검사도 인덱스를 생성했다. 8회 비교에서 Tax의 느린 표본이 있어 이를
별도 보존하고, 기존 인덱스만 재사용하는 최종안으로 조정했다. 최종 시간·화면 검증은 별도로
기록하며 초기안의 수치를 최종 평균에 섞지 않는다.

최종안은 VCM·Tax 각각 두 쌍씩 새 워커에서 교대 비교했다. 총 8회 모두 완료했으며 의존성·
CSS 바이트·감시 경로·진단·컨텍스트 근거·대상 원문 해시가 같았다. 느린 표본도 포함한다.

관찰된 Node와 native esbuild 합산 RSS의 표본 최대값은 VCM 943→995 MiB, Tax
2,069→1,988 MiB였다. 1초 간격 관찰값이며 엄밀한 최대 RSS 측정은 아니다. 기존 3 GiB Node·
1 GiB native·4 GiB 합산 진단 보호와 제품 메모리 정책을 유지했다. 컨텍스트 탐색은 같은 코드인데도
표본 간 시간이 달라졌다. VCM의 감소나 Tax의 작은 증가를 일반적인 개선·퇴행률로 단정하지
않으며, 확인한 직접 효과는 같은 추론 결과에서 보조 검사의 반복 하위 구문 탐색을 줄인 것이다.

화면 검증은 설치본과 수정본의 VCM·Tax·UDT 상세 화면을 비교했다. 세 크기(390·768·1440)의
계산된 스타일이 같았다. VCM은 실제 투자자 정보가 출력되나 양쪽 모두 기존 `partial-blocked`
판정이 남고, Tax는 양쪽 모두 대상 출력과 `ready`를 확인했다. UDT 상세 화면은 양쪽 모두
주변 `PosterCardScrollBox`의 `undefined.length`로 실패했다. 배열 사용을 추론한 대체 값은
존재하므로 실제 Query 반환·소비 흐름의 추가 조사가 필요하다. 이 사례를 성공에 포함하지
않으며 이번 변경으로 해결됐다고 주장하지 않는다.

동일 UDT 파일의 경로 전환은 현재 고정 입력의 후보 ID로 설치본과 수정본 각각 8회를 비교했고
모든 화면 문구·선택 ID·안정화 판정이 일치했다. 7회 전환은 같은 문서의 HMR을 유지했다.
첫 하네스는 예전 후보 ID를 사용해 다른 첫 화면이 열렸고, 완료 신호만으로 통과시키던 검증
누락을 발견했다. 그 실행은 별도 보존하고 최종 성공 집계에서 제외한다. 최종 검사는 매 경로의
실제 화면 문구·선택 ID·안정화 판정과 생성 CSS·의존성·컨텍스트를 비교한다. 실제 VS Code
작업창을 재로드한 검증은 아니다. 각 브라우저는 종료와 무리스너 상태를 확인하고 모델 보존
정책을 검사한 뒤 전용 임시 프로필을 즉시 정리한다.

증거는 `.tmp/preview-resume-1695-20261026t1005z/`에 보관한다. 비교는 고정한 허용 소스와
동일한 설치 의존성·네이티브 esbuild 경로를 사용한다. 프로젝트 설정이나 서버를 실행하지
않으며 브라우저 검증은 CDP 파이프로 전달한 산출물을 사용한다. 외부 부하와 OS 캐시를
통제한 실험이 아니므로 작은 표본의 시간 차이를 일반적인 속도 개선율로 주장하지 않는다.
