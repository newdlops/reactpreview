# 복구 신경망 사전학습과 배포 모델

이 문서는 0.1.1515의 **v1 학습 기록**입니다. 현재 0.1.1516의 모델·안전 경계·검증 결과는
[사전학습 v2](neural-pretraining-v2.md)를 참고하세요. 아래 v1의 수치와 당시 정책은 보존합니다.

0.1.1515는 기존 프로필별 온라인 학습 앞에 읽기 전용 복구 사전학습 모델을 추가합니다.
대형 언어 모델처럼 임의 코드를 이해하거나 새 복구 코드를 생성하는 구조가 아닙니다.
컴파일러와 기존 resolver가 허용한 후보 중 먼저 시도할 후보를 고르는 구조적 순위 모델입니다.

## 모델과 안전 경계

- 입력: 128칸. 제한된 전략·역할 토큰 96칸과 충돌 없는 수치 특징 32칸.
- 구조: `128 → 512 ReLU → 128 ReLU → 1 sigmoid`, 학습 파라미터 131,841개.
- 학습: 모든 층의 가중치와 bias를 mini-batch Adam으로 학습. 배치 256, 조기 종료 patience 10.
- 배포: 층별 int8 양자화 131,841바이트, base64 175,788바이트. NumPy·GPU·원격 서버는 불필요.
- 모델 ID: `recovery-prior-v1-13fb220a70ad`.
- 가중치 SHA-256: `13fb220a70ad7810dea3ce0c8110c3663e4b86e336bf8b850126a300301b6937`.

지원되는 유형은 중첩 예외 값, 컬렉션 필터, 참조값 일치, 페이지 선택, 페이지 실행, 로컬 UI 전환입니다.
판단할 수 없는 선택지·미지원 유형·혼합 포트폴리오·불완전한 특징에서는 기존 정책으로 돌아갑니다.
학습 데이터의 수치 범위를 로그 공간에서 0.12 이상 벗어나는 입력에도 적용하지 않습니다.
최고 점수 0.8 이상, 2위와 격차 0.2 이상일 때만 사전값을 사용하며 이 점수는 성공 확률이 아닙니다.

동일 문맥에 검증된 후보 기록이 하나라도 있으면 후보 묶음 전체에서 사전값을 사용하지 않습니다.
새 문맥에서는 기존 온라인 헤드 점수를 `min(0.75, evidence / (evidence + 32))` 비중으로 혼합합니다.
실패한 후보의 우선순위·시도 제외·분기 유지·사용자 정지·수동 선택·재시도 예산은 기존 정책이 우선합니다.
정렬만으로 성공 처리하지 않으며 실제 소유 출력의 연속 관찰과 rollback 검증을 계속 요구합니다.
사전 점수는 진단의 `priorScore`와 `priorVersion`에만 남습니다. 온라인 업데이트·성공·시도 횟수는
증가하지 않고, 버전 3·4 프로필 모델과 최대 192개의 익명 결과 기록을 그대로 사용합니다.

가중치는 지원 후보가 둘 이상일 때 한 번만 디코딩합니다. 형식·차원·스케일·바이트 수·체크섬이 틀리면
적용하지 않습니다. 64개 익명 특징 벡터의 점수만 메모리에서 캐시하며 해시가 같아도 모든 칸을 대조합니다.
원문·후보 ID·순위·프로젝트 경로·임의 텍스트는 사전학습 입력이나 모델 파일에 넣지 않습니다.
새로운 런타임 의존성, 외부 모델 요청, 다운로드, 텔레메트리는 없습니다.

## 학습 데이터와 선택 기준

`scripts/neural-recovery/corpus.mjs`의 저장소 소유 React 실행 실험을 사용했습니다.
후보를 실제로 적용해 `renderToStaticMarkup`에서 목표 출력이 나왔는지와 예외 발생 여부로 라벨을 얻습니다.
기존 코드의 우선순위나 신경망 예측을 정답 라벨로 복사하지 않습니다. 사용자 소스·데이터·로그는
수집하거나 배포하지 않았으며 모델은 이 저장소의 라이선스를 따릅니다.

| 구분      | 복구 사례 | 실행된 후보 결과 | 서로 다른 특징 벡터 |
| --------- | --------: | ---------------: | ------------------: |
| 학습      |    36,000 |          111,313 |              35,755 |
| 검증      |     9,000 |           27,716 |              14,218 |
| 최종 평가 |     9,000 |           27,927 |              14,394 |

각 구분은 다른 시드·조합 템플릿·수치 구간을 사용하며 구분 간 동일 특징 벡터는 0개입니다.
데이터 시드는 20260908, 초기 가중치 시드는 `20260907 + 첫 은닉층 폭`입니다.
학습은 NumPy 2.3.3을 사용하고 BLAS 스레드 한도를 2로 설정했습니다.
한도를 100 epoch로 설정하되 실제로는 검증 손실이 개선되지 않으면 조기 종료했습니다.

| 구조          | 파라미터 | 수행 / 채택 epoch | 양자화 후 검증 손실 | 검증 첫 시도 성공 |
| ------------- | -------: | ----------------: | ------------------: | ----------------: |
| 128→128→32→1  |   20,673 |           41 / 31 |            0.074267 |            93.78% |
| 128→256→64→1  |   49,537 |           35 / 25 |            0.074457 |            93.78% |
| 128→512→128→1 |  131,841 |           39 / 29 |            0.073672 |            93.78% |

모델 선택에는 검증 구분의 첫 시도 성공, 시도 수, 양자화 후 손실 순서만 사용했습니다.
세 모델의 복구 순위 성적은 같았으며 가장 큰 모델은 검증 손실이 조금 더 낮았습니다.
최종 평가 데이터는 선택 후에만 평가했습니다. 학습 3회 합계 115 epoch·50,025개 배치 업데이트이며,
채택 가중치는 마지막 epoch가 아니라 512 모델의 29번째 epoch 체크포인트입니다.

## 관측한 성능과 한계

분리한 최종 평가 9,000건에서 콜드 시작 첫 시도 성공은 7,560건(84.0%)에서 8,397건(93.3%)으로
늘었습니다. 해결 가능한 8,782건의 평균 시도 수는 1.2324에서 1.0629로 줄었습니다.
예외·컬렉션·참조값·로컬 UI 템플릿에서는 기존 정책과 같고, 개선은 페이지 선택과 실행 순서에서 나왔습니다.
허용 후보로 해결할 수 없는 218건은 모델을 키워도 해결된 것으로 처리하지 않습니다.

실제 생성 런타임으로 동일 9,000건을 다시 실행했을 때 콜드 선택·보류·시도 수가 학습 평가와 일치했습니다.
128개 양자화 대조 벡터의 NumPy/JavaScript 최대 점수 차이는 `9.31e-8` 미만이었습니다.
같은 런타임의 온라인 학습을 유지한 순차 복구에서는 첫 시도 성공 8,441→8,584건,
전체 시도 9,690→9,498회, 최종 해결 8,782→8,782건이었습니다.

최종 디코더에서 이 장비의 3후보 최초 선택은 가중치 준비를 포함해 약 15.5ms,
반복 선택 중앙값 0.392ms·95백분위 0.443ms였습니다. 순차 실험의 판단·학습 경과 시간은
기존 약 6.76초에서 약 9.36초로 늘었습니다. 줄어든 재렌더 시도가 이 비용을 상쇄하는지는 실제
프로젝트에서 별도로 측정해야 하며, 전체 렌더링 시간이 빨라졌다고 단정하지 않습니다.

격리된 Chromium의 nonce 전용 CSP에서도 모델을 실행했습니다. 첫 선택은 약 22.7ms였고
외부 리소스 요청·CSP 위반은 0개였습니다. 최초 사전 선택은 온라인 학습 횟수를 늘리지 않았고,
실패 라벨을 적용한 뒤에는 사전 후보 대신 다른 허용 후보로 전환했습니다. 이는 런타임 검사이며
실제 사용자 페이지나 다양한 화면 크기의 시각 검증은 아닙니다.

이 수치는 여섯 구조적 합성 실험의 SSR 결과입니다. 브라우저의 비동기 부작용·레이아웃·실제 백엔드·
사용자 의도·모든 JavaScript 예외를 대표하지 않습니다. 숨은 조건의 값을 입력만으로 알 수 없는
경우도 남겨 두었습니다. 같은 생성기 안의 분리 평가이므로 독립적인 실제 프로젝트 벤치마크는 아닙니다.
모델 용량이나 학습 반복을 더 늘리는 것만으로 이런 정보 부족을 해결할 수 없습니다.

## 재현과 배포 예산

현재 학습 스크립트는 v2로 갱신되었습니다. v1의 정확한 재현에는 v1 시점의 생성기·인코더·학습 코드가
필요하며, 현행 재현 명령은 [v2 문서](neural-pretraining-v2.md#재현)를 따릅니다.

`uv`의 NumPy 설치는 선택적 개발·학습 도구이며 확장 설치에는 필요하지 않습니다.
학습은 임시 디렉터리에 후보 산출물만 생성합니다. 검토한 `model-artifact.ts`를
`previewInspectorRecoveryPriorArtifact.ts`에 반영한 뒤 런타임 대조·회귀·패키지 검증을 다시 수행해야 합니다.
학습 스크립트가 사용자 프로필 모델을 변경하거나 스스로 설치·게시하지 않습니다.

프로젝트 예산은 모델 140,000개 파라미터·base64 200,000바이트 이하, 현재 darwin-arm64 VSIX 20MiB 이하입니다.
이는 Marketplace의 공인 용량 한도가 아니라 이 프로젝트의 로딩·메모리·패키지 관리 기준입니다.
[공식 배포 안내](https://code.visualstudio.com/api/working-with-extensions/publishing-extension)에 따라
플랫폼 전용 VSIX와 포함 파일·의존성을 검증합니다. 이 작업은 Marketplace 게시나 게시 승인을 뜻하지 않습니다.
