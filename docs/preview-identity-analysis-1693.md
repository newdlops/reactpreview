# 0.1.1693: 페이지 후보 이름 분석과 정렬 비용 축소

페이지 후보와 프레임의 역할을 판정할 때 같은 이름을 반복 분해했다. 현재 완성된 이름 문자열을
매번 읽고, 해당 근거 객체의 직전 입력과 같을 때만 문법 토큰을 재사용한다. 객체를 키로 하는
약한 참조를 사용하며 객체 자체나 파일시스템·경로 해석 결과를 보관하지 않는다. 서로 다른
이름으로 변경되면 즉시 다시 분석하며, frozen 객체의 getter도 예외로 처리하지 않는다.

객체별 최근 문자열 하나만 보관하고, 4,096 UTF-16 코드 단위를 넘는 이름은 보관 없이 분석한다.
이 기준은 보관량만 제한하며 분석·출력 범위는 줄이지 않는다. 기존 단독 토큰화 함수는 여전히
매번 독립적인 결과를 반환한다. 전체 점수·현재 체크포인트·깊이·소유자 보너스는 저장하지 않는다.

같은 렌더 경로의 유한한 점수는 정렬 대신 안정적인 최대값 순회로 선택한다. 동점이면 먼저
발견한 후보가 유지된다. NaN 점수가 섞이면 기존 안정 정렬을 그대로 사용한다. 경로 식별자,
선택된 라우트, Provider, 프레임 판정 기준과 탐색·메모리·120초 단계 정책은 바꾸지 않는다.

반복 점수 검사에서 이름 분해는 40회에서 1회로 줄었다. 관련 Inspector 검사 1,034개가
통과했다. 기존 소스 바이트를 보존한 비교에서 역할 판정 8,606건·후보 선택 2,340건·전체 페이지
구성 2,340건이 같았다. 변경 가능한 이름·getter·동점과 비유한 점수도 비교에 포함했다.
합성 후보 선택 작업 네 쌍은 약 138~~144ms에서 50~~52ms로 줄었으나 전체 프리뷰 시간은 아니다.

실제 production SDK로 Tax 두 쌍과 UDT 한 쌍을 별도 새 워커에서 순차 준비했다.
6회 모두 완료했고 의존 경로·CSS·컨텍스트·진단이 같았다. 프로파일링은 시간 비교에서 제외했다.

시간은 양방향으로 변했다. Tax의 전체 차이는 작고 UDT는 한 쌍뿐이다. 일반적인 속도 향상이나
모든 파일의 렌더링 성공률 개선으로 해석하지 않는다.
