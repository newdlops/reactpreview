# 읽기 전용 분석의 구문 트리 재사용

목표는 기존 프리뷰 기능을 유지하며 첫 번들 준비 시간을 줄이는 것이다. 실제 FiStaApp의
0.1.1646 진단에서 대상 출력 관측은 탐색 후 약 589ms, 첫 번들 준비는 약 17.76초였다.
첫 준비의 파싱 호출은 11,172회이며 정확한 파일·내용·옵션 조합은 3,798개였다.
진단 계측의 시간은 성능 비교 결과로 사용하지 않는다.

## 범위와 불변식

- 순수한 구문 분석 8곳에서만 `Latest`, 부모 포인터, 기존 ScriptKind의 파싱을 공유한다.
- 경로 철자·소스 문자열·ScriptKind가 모두 같아야 같은 트리를 재사용한다.
- 파일 읽기·경로 확인·구성 해석·모듈 해석은 기존 호출 경로를 유지한다.
- 오류 문법의 진단과 fail-open/fail-closed 판정, 방문 순서·위치·분석 한도는 같다.
- 타입 프로그램·변환용 AST와 타입 문맥에 의존하는 결과는 이 캐시를 사용하지 않는다.
- AST는 WeakRef로만 보관한다. 문자열 환산 보관량은 4MiB, 항목은 512개,
  개별 소스는 128Ki UTF-16 코드 단위 이하로 제한하고 오래된 항목부터 버린다.
- 소스가 바뀌거나 트리가 회수되면 다시 파싱한다. 컴파일러 종료 시 저장 문자열도 해제한다.
- 호출자는 공유 트리를 변형하거나 체크러·변환기에 전달하지 않는다.
- 원본 `/Users/lky/project/rtcc-poc-page`는 읽기 전용이며 설정·스크립트·서버를 실행하지 않는다.
- 모든 새 로컬 리스너는 기존 PortManager 전용 주소 `127.1.0.1`을 사용한다.
- 시스템 서비스·자동 실행·관리자 권한·보안 및 VPN 정책 변경은 하지 않는다.
- 새 의존성, commit, tag, push, Marketplace 게시를 추가하지 않는다.
- 기존 변경을 보존하며, 삭제 전 지정된 모델 보존 정책으로 정확한 임시 경로를 확인한다.
- 모든 유지보수 텍스트는 1,000줄 이하로 유지한다.

## 완료 근거

실제 파서의 구문·부모·위치·진단, 소스 편집·경로 및 문법 분리, 보관 한도·회수·종료를 검사한다.
8개 분석 결과가 기존과 같고 같은 문법의 읽기 전용 분석들이 한 번 파싱한 트리를 사용해야 한다.
계측 없는 배포용 워커를 버전별 5개씩 AB/BA/AB/BA/AB 순서로 비교한다. 각 워커의 첫 준비와
재준비, Node CPU를 기록하고 모든 표본·활동·출력 범위를 보존한다. 효과가 불확실하면 추가
근거를 모으며 최초 준비 개선을 확정했다고 표현하지 않는다.

브라우저 출력은 기존과 비교하고 실제 Chromium의 대상·중첩 마운트와 정리를 확인한다.
전체 `npm run check`, production VSIX·네이티브 의존성·측정 워커 일치를 확인한 뒤 버전을
한 번 올려 로컬 재설치한다. 설치 파일·설정·학습 기록·원본 보존과 임시 데이터 정리를 확인한다.
