# 복구 힌트 플러그인의 불필요한 import 처리 축소

## 변경

관련 힌트가 비어 있으면 패키지·스타일 해석과 서버 파일 처리기를 등록하지 않는다.
힌트가 있으면 정확한 모듈 요청 문자열을 네이티브 필터로 전달한다. 관련 없는 import는
JavaScript 복구 콜백과 실제 경로 조회를 거치지 않고 기존 해석기로 진행한다.

문자열은 힌트 키를 만들 때 한 번 읽어 고정한다. 정규식 특수문자는 리터럴로 취급하고,
ASCII 밖의 문자열이나 큰 필터는 기존의 넓은 필터와 정확한 집합 조회로 처리한다.
패턴 길이 제한은 힌트나 그래프를 잘라내는 한도가 아니다.

관련 요청은 여전히 실제 importer 경로를 확인하고 작업공간 경계를 검증한다. 정상 패키지
해석이 복구 계약보다 우선한다. 서버 소스의 경계 표시는 재빌드마다 다시 읽는다.
경로·파일 상태의 새 캐시는 만들지 않으며 기존 CSS·Provider·경로 선택·리소스 상한과
타임아웃·CSP는 변경하지 않는다.

## 검증

- 실제 두 모듈 번들의 힌트 없는 처리 호출은 해석 4회·파일 읽기 처리 2회에서 모두 0회로
  줄었으며 원본 출력과 경고 없는 정상 해석을 유지했다.
- 관련 없는 요청, 정규식 문자가 있는 패키지·CSS, 비 ASCII 요청과 큰 힌트 목록을 검사했다.
- accessor가 나중에 다른 요청 문자열을 반환해도 최초 힌트 키와 필터의 일치를 유지한다.
- 다른 이름의 심볼릭 링크 importer는 정상 처리하며, 재빌드 전에 작업공간 밖으로
  재지정하면 이전 힌트로 복구하지 않는다.
- 기존 서버 계약·학습 예제·타입 출력·정상 스타일 우선순위 검사와 함께 16개 테스트가 통과했다.
- 전체 `npm run check`: 739개 파일·5,803개 테스트와 줄 수·타입·린트·포맷·빌드 통과.
- darwin-arm64 production VSIX를 로컬 설치하고 런타임 2,461개 파일의 일치와 설정·학습
  파일 9개의 내용·권한 보존을 확인했다. 이전 설치본과 달라진 런타임은 compiler worker뿐이다.
- 실제 검색 페이지의 최초 준비·재준비에서 복구 해석 콜백은 각각 20,950→0회,
  실제 경로 검사는 13,986→3,683회로 줄었다. 필요한 서버 파일 처리 3,663회는 유지했다.
  이 계측은 별도 worker에만 넣었으며 설치할 제품 번들에는 포함하지 않는다.
- 같은 부모 프로세스와 런타임 경로 조건으로 검색·VCM을 ABBA 순서로 16번 준비했다.
  문맥·의존성·모든 CSS·청크 수가 같고 새 오류·경고 종류가 없다. 기존 경고의 첫 참조 위치와
  재준비 시 표시 횟수, JavaScript 청크 지문은 실행마다 달라 별도로 기록한다.
- 시스템 메모리 압축량이 약 20GiB인 구간에서 번들링 전 단계까지 큰 시간 편차를 보였다.
  검색의 최초 준비가 짧아진 표본과 VCM이 더 느린 표본을 모두 보존하며 전체 준비 시간의
  개선율을 확정하지 않는다. 네이티브 창의 시각 검증은 이번 변경에서 수행하지 않았다.

실제 준비 시간과 전체 검사·로컬 패키지 검증 결과는
`.tmp/preview-bundle-analysis-1702-20261027t0354z/`에 보관한다. CPU 프로파일은 TCP 포트를
열지 않는 전용 worker에서만 수집했으며 계측 실행을 성능 개선율에 포함하지 않는다.
