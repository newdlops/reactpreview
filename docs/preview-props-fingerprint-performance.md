# React 소유자 그래프를 제외한 props 변경 감지

0.1.1670은 Inspector의 props 변경 감지용 지문에서 React element의 내부 `_owner` 연결을 제외합니다. 실제 props 객체와 자식, 편집용 JSON, 저장된 사용자 설정·학습 상태는 보존합니다.

## 원인과 수정

기존 실제 공통 섹션 페이지의 유효한 브라우저 CPU 프로파일 5개에서 `stringifyPreviewInspectorProps`가 표본 실행 시간의 약 84~85%를 차지했습니다. 변경 감지 중 React element의 내부 소유자 연결을 통해 Fiber와 페이지 상태까지 JSON으로 따라갔습니다. 이 긴 동기 작업은 다음 탐색과 타이머도 늦출 수 있습니다.

- 실제 base props는 매번 최신 값으로 보관합니다. 같은 공개 데이터의 소유자만 바뀌면 불필요한 Inspector 갱신을 요청하지 않습니다.
- React18/19의 own element 표식을 확인한 경우에만 `_owner`를 제외한 JSON 전용 사본을 만듭니다. 원본 element나 props를 바꾸지 않고 소유자 getter·toJSON을 읽지 않습니다.
- 자식 내용·일반 중첩 데이터·공개 사용자 필드의 변경은 계속 감지합니다. 일반 데이터에 있는 `_owner`는 제외하지 않습니다.
- 기본 편집·저장 JSON의 함수·심볼·bigint·순환 참조·프로토타입 필터는 같습니다. 새 캐시나 노드·깊이·데이터 한도를 도입하지 않습니다.

## 측정 범위와 한계

최초 4개 대상의 AB/BA32회는 모두 정상 준비됐고 16쌍의 CSS·의존성·진단·선택 문맥·감시 경로가 같았습니다. 다만 작은 페이지의 재실행이 화면별 비회귀 기준을 넘어 최초 판정은 실패로 보존했습니다.

변경 없이 그 페이지를 독립적으로 32회 더 대조했습니다. 처음 느렸던 표본을 포함한 총64회와 32쌍을 모두 보존했습니다. 대상별 전체 쌍의 기하 평균을 계산하고, 네 대상에는 같은 비중을 부여했습니다. 표본을 추가한 페이지가 전체 결과를 과도하게 좌우하지 않도록 했습니다.

| 실행 | 컴파일 변화 | 전체 준비 변화 |
| ---- | ----------: | -------------: |
| cold |   0.8% 증가 |      8.3% 단축 |
| warm |   4.1% 단축 |     13.7% 단축 |

같은 번들끼리의 별도32회 대조에서도 상당한 시간 편차가 있었습니다. 위 수치를 임의의 모든 파일이나 Discovering component context·Bundling reachable modules 각각의 보장 개선율로 해석하지 않습니다. 직접 확인한 원인은 props 변경 감지의 렌더러 비용입니다.

## 기능·보존 검증

- 새10개 단위 검사와 관련7파일·70회귀 검사를 통과했습니다. 256개를 넘는 일반 데이터의 뒤쪽 변경과 동일 객체의 내부 변경도 확인했습니다.
- 실제 GP 조합원 페이지를1440×900,768×1024,390×844에서 비교하고 Tab,초대·취소,캐시 새로고침2회를 실행했습니다. CSS·계산 스타일과12장의 실제 화면을 비교했습니다.
- 릴리스 절차는 전체 `npm run check`, production VSIX 검증, 정확한 VSIX의 로컬 재설치와 설치 파일의 바이트 검증을 요구합니다. 실행 결과는 이 작업의 증거 디렉터리에 기록합니다.
- Node4GiB,네이티브2슬롯·256MiB,Sass512MiB·30초,유휴15초와 소스·그래프·출력·캐시·관찰 한도를 유지합니다.
- 앞선3슬롯·384MiB 후보는 준비 증거 부족으로 철회했으며 이번 릴리스에 포함하지 않습니다.
- 사용자 프로젝트·기존 작업·설정·학습 기록을 보존합니다. 자동 실행 등록, 별도 상주 서비스, 관리자 권한이나 시스템·보안·VPN 정책 변경은 없습니다.
