# 경로별 성공을 유지하는 자동 후속 빌드 축소

## 변경

같은 파일의 서로 다른 호출 경로와 라우트는 계속 검사한다. 한 경로가 전체 페이지 문맥과
지속 출력을 검증하면, 같은 경로의 나머지 마운트 옵션을 자동으로 다시 컴파일하지 않는다.
옵션 자체와 수동 선택은 유지하고, 실행하지 않은 옵션을 평가·성공으로 기록하지 않는다.

부분 문맥·검증 전의 저장된 선호·출력이 회귀한 경로·고정된 로딩 체크포인트는 이 생략의
근거가 아니다. 다른 라우트와 호출 위치는 기존 경로 식별자로 구분한다. 이미 검증된 전체
페이지와 같은 경로의 중복 복구 재생도 생략하며, 실제 출력이 사라진 경우의 복구는 유지한다.

경로의 검사 횟수는 실제 실행 횟수다. 자동 검사가 끝나면 기존 `STABLE OUTPUT` 표시를
사용하고 남은 마운트 옵션은 계속 직접 선택할 수 있다. 스타일과 컨트롤 구조는 유지한다.

## 검증 범위

- 설치된 0.1.1697의 실제 worker·TypeScript 표준 선언·네이티브 의존성을 사용한 새 창 직접
  진입에서, 상세 화면 5개와 Sparkle 배경 7개 경로가 모두 ready였다. 지정한 경로 유지,
  실제 대상 출력·전체 페이지 문맥·blocker 없음과 자동 후속 빌드 0회를 확인했다.
- 같은 정상 의존성의 상세 화면 자동 선택은 0.1.1697에서 후속 빌드 9회였다. 이번 후보는
  서로 다른 5개 경로를 검사하면서 후속 빌드 4회 후 ready에 도달했다.
- 수정 전 검증 스크립트의 삭제된 0.1.1696 참조로 표준 Array·Promise 타입이 빠진 실행은
  제품 성공률과 성능 근거에서 제외했다. 현재 설치본의 파일 존재와 버전을 확인한 뒤 실행한다.
- 후보의 새 창 직접 진입은 12/12, 순서를 바꾼 경로 전환·복귀는 14/14 성공했다. 각 수동
  선택의 경로 ID를 확인했으며 자동 후속 빌드는 없었다. 비교한 12개 경로의 원본 입력,
  의존성, CSS, 진단과 정적 문맥 범위는 기존 설치본과 같았다.
- 상세 화면 자동 탐색에서 누적 번들링 시간은 약 10.2초에서 5.3초로 줄었다. 같은 입력의
  각 1회 측정이며, 모든 프로젝트의 로딩 시간이 같은 비율로 줄어든다는 의미는 아니다.
- `npm run check`를 통과했다(734개 파일, 5,761개 테스트). 전체 문맥이 없는 경우, 출력 회귀,
  다른 라우트, 저장된 선호, 고정된 로딩 상태와 수동 옵션 유지도 회귀 검사에 포함했다.
- production 빌드·darwin-arm64 VSIX를 검증하고 0.1.1698을 로컬 설치했다. 설치된 런타임
  2,461개 파일은 패키지와 일치하며 설정·학습 파일 9개의 내용과 모드는 보존됐다.
- 전용 VS Code 창에서 실제 Provider를 통한 멤버·관리자·로그아웃 분기와 권한별 버튼 상태,
  모달 입력·Escape 닫기를 확인했다. 상호작용 후에도 `PAGE READY`, `Console (0)`이었다.
- 상세 화면과 Sparkle 화면을 390·768·1440px에서 시각 검사했다. 외부 영상 iframe은 기존
  CSP로 차단되어 있고, Sparkle의 결과 준비 화면은 해당 페이지의 로딩 표시를 유지한다.

재현 입력과 개별 결과는 `.tmp/preview-path-success-1697-20261026t1635z/`의 검증 기록과
그 기록이 참조하는 개별 케이스에 보관한다. 검증 종료 시 소유 브라우저를 종료하고 해당
임시 프로필을 정리하며, 사용하지 않는 실험 SDK는 압축 보관한 뒤 정리한다.

외부 서비스 로그인과 외부 영상 iframe 재생은 이번 검증 범위에 포함하지 않는다.
기존 CSP의 `frame-src 'none'`은 유지한다. 원본 프로젝트·시스템 설정·권한·VPN 정책을
변경하거나 서버·상주 서비스를 만들지 않는다.
