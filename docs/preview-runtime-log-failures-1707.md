# 최근 실패 로그의 공통 분기 오류와 남은 한계

2026-10-27 20:01~20:07 KST의 VS Code 회전 로그 3개에서 런타임 이벤트 1,032개를 조사했다.
등록된 버전은 0.1.1706이며, 설치 이후 재시작한 VS Code가 20:01에 확장을 활성화했다.
이번 기록을 이전 버전이 남은 창의 로그로 취급하지 않는다.

## 확인한 실패

- payroll의 `rtcc-investor-table.tsx`에서 `null.src` 오류 2회, `rtcc-judgment-chip.tsx`에서
  같은 오류 4회가 발생했다. 대상 출력이 없고 경로 검증 실패도 기록됐다.
- 공통 상위 컴포넌트 `RtccSummaryV3Inner`의 `relations != null`은 false였으나,
  자동 복구가 이 관계도 분기를 열었다. 관계도 값은 여전히 null이므로 `.src`에서 실패한다.
- 같은 조건을 오류 뒤 되돌리고 다시 여는 기록도 있다. 칩의 한 리비전에서 렌더 시도가
  34회여서, 컴파일 속도와 별도로 런타임 복구 비용이 크다.
- `AgGridTableProvider`의 `api.addEventListener`와 `this.api.removeEventListener`가 함수가
  아니라는 effect 격리 기록 14회도 남아 있다. 이 오류와 최종 대상 도달 실패의 인과관계는
  이번 분기 수정만으로 입증하지 않는다.

## 변경과 보존 범위

실제 컴포넌트 단계와 공유 래퍼 이름을 구별한다. `FlexBox`가 대상 경로를 감싸는 래퍼라는
사실만으로, 같은 이름의 래퍼를 쓰는 옆 관계도 분기까지 대상 경로로 인정하지 않는다.
자동 대상 탐색과 neural 조건 후보 필터가 같은 제한을 사용한다.

명시적 대상 분기 근거, 실제 컴포넌트 단계, 반복 컴포넌트의 보수적 이름 근거, 대상 자체의
UI 상태와 수동 선택을 유지한다. JSX 위치 표식이 없는 기존 경로에도 적용한다.
CSS·테마·원본 프로젝트·데이터·성공 판정과 실행 제한을 변경하지 않는다.

## 검증 및 한계

- 실제 로그와 같은 표식 없는 경로와 공유 래퍼 사례를 기존 코드에서 재현했다.
  새 9개 사례 중 6개가 수정 전 실패했고, 수정 후 관련 회귀 검사 31개가 통과했다.
- 실제 실패 파일과 로그상 성공했던 조합원 초대 페이지를 원본 읽기 전용으로 비교했다.
  같은 첫 실행 단계에서 투자자 표의 `null.src` 예외는 4→0회, 판단 칩은 6→0회였다.
  두 대상은 `post-commit-failed`에서 `partial-blocked`로 바뀌었으나 대상 출력은 여전히 없다.
- 기존 성공 페이지는 수정 전후 `ready`였다. 실제 마우스·키보드로 검색어 `Name 2`를
  입력해 3→1행, 지워서 1→3행 복원을 확인했고 Tab 이동도 검사했다. 초대 발송은 하지 않았다.
- 세 대상의 원본 파일과 모든 CSS 청크 해시는 수정 전후 같았다. 판단 칩의 의존성 개수는
  2,332→2,331개이므로 전체 의존성 그래프가 동일하다고 표현하지 않는다.
- 390·768·1,440px 화면을 직접 확인했다. 초대 페이지의 검색·표·푸터는 유지됐다.
  모바일 표는 일부 열만 보이며, 데스크톱의 개발 안내는 서로 겹친다. 이번 변경은 이 원본
  화면을 재설계하지 않는다. RTCC는 제목과 `투자자 0곳`만 보여 완성된 화면 검증에 실패한다.
- `npm run check`가 통과했다. 745개 테스트 파일, 5,870개 검사를 포함한다.
- 원본 쓰기 시도 0건과 검증 자원 잔류 0건을 19개 guard 보고서로 확인했다.
- RTCC의 관계도 분기를 닫아도, 페이지 문맥의 대상 출력은 별도로 증명해야 한다.
  `null.src` 제거를 RTCC 전체 성공으로 표현하거나 성공 조건을 완화하지 않는다.
- 후속 실행의 90초 검증 범위가 준비 중 끝난 표본은 완결된 제품 실패·성공으로 판정하지
  않는다. 저장한 시점의 `partial-blocked`와 준비 중 상태를 함께 보존한다.
- 후속 준비는 전후 모두 4회여서 감소 효과를 확인하지 못했다. 전체 프리뷰 속도나 RTCC
  렌더링 성공률이 해결됐다고 주장하지 않는다. 다음 조사 대상은 AG Grid API 호환과
  실제 대상까지 전달되는 데이터·페이지 문맥이다.

증거와 원시 결과는 `.tmp/preview-live-failures-1707-20261027t1107z/`에 보관한다.
0.1.1707의 production 패키지와 설치된 런타임 2,461개 파일을 비교했고, 설정·학습 기록
9개를 보존했다. 종료된 검증 프로필 11개와 중복 워커·개발 소스맵을 정리해 논리 용량 약
417MiB를 회수했다. 압축 재현 자료와 로그·화면·현재/직전 VSIX는 남겼다.
네이티브 VS Code 창을 재로드하거나 설치 이후 화면을 확인한 것으로 표현하지 않는다.
