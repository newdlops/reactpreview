# 소스 파일 검증의 동시 요청 공유와 소유권 보호

`PreviewProjectFileAnalysisCache`는 파일 메타데이터와 Yarn 아카이브 지문을 확인하기 전에
읽기 소유권을 확보한다. 초기화나 새 편집 뒤에 늦게 끝난 이전 검사가 새 읽기의 소유권을
가져가거나, 새 캐시를 지우거나, 다른 요청의 미완료 읽기를 제거하지 않는다. 이전 요청은
자신이 읽은 결과를 받으며 현재 캐시에는 반영하지 않는다.

같은 정규화 경로와 byte 상한의 동시 요청은 확인부터 읽기까지 공유한다. 서로 다른 상한은
공유하지 않는다. 완료한 확인은 보관하지 않으므로 다음 순차 요청은 저장·삭제·크기 변경을
다시 확인한다. 미저장 편집이 우선하며, 소스 128MiB·16,384개 상한과 Yarn 검증은 유지한다.
콜드 읽기는 기존처럼 직접 열어 handle의 종류와 크기를 확인한다.

## 검증

- 기존 코드에서 9개 회귀 사례의 실패를 먼저 재현했다. 초기화와 초과 크기 스냅샷 뒤의
  이전 메타데이터 검사, 서로 다른 byte 상한의 경합, 동시 검사의 중복을 포함한다.
- 신규 11개 사례는 디스크·Yarn 검증의 소유권, 읽기 공유, 변경·삭제·디렉터리·크기 초과,
  순차 요청의 새 변경 관찰을 검사한다. 기존 파일·동시 읽기·상위 문맥 캐시를 포함해
  관련 검사 37개가 통과했다. 실제 zip 파싱은 기존 실제 아카이브 검사도 유지한다.
- 전체 `npm run check`: 744개 파일·5,861개 테스트와 줄 수·타입·린트·포맷·빌드 통과.
  첫 샌드박스 실행은 전용 루프백 `listen EPERM` 등 브라우저·프로세스 제약으로 17개가
  실패했다. 로그를 보존하고 승인된 실행 환경에서 전체 검사를 다시 통과했다.
- 사용자 원본 소스는 읽기만 하며 프로젝트 스크립트나 서버를 실행하지 않는다.
- UI, 경로 선택, CSS, 번들 재시도 정책, 메모리 상한, 시스템 정책은 변경하지 않는다.
  네이티브 창의 화면 검사와 재로드는 이 작업에서 수행하지 않는다.

## 동시 검증 구간 측정

VCM 소스를 실행하지 않고 검증용 파일 64개에 저장했다. 두 버전이 같은 record 내용과
객체를 재사용하는지 확인하며, 수정 전·후 순서를 교대한 7회 중앙값을 기록했다.

| 파일당 동시 요청 | 메타데이터 조회 전→후 | 처리 시간 전→후 |
| ---------------- | --------------------- | --------------- |
| 1개              | 64→64회               | 0.451→0.443ms   |
| 8개              | 512→64회              | 1.839→0.933ms   |
| 32개             | 2,048→64회            | 5.997→2.522ms   |

이는 동시 요청의 파일 검증 비용이다. 하나의 실제 VCM 프리뷰를 최초·재준비한 초기 계측에서는
겹치는 소스 읽기가 없었다. 따라서 이 표를 전체 프리뷰 준비 속도 개선율로 해석하지 않는다.
당시 경로 해석 조회는 약 2만4천 회였고, 캐시 용량에 따른 재조회도 관찰했으나 이번에는
경로 캐시의 용량이나 해석 결과 재사용 범위를 늘리지 않았다.

## 실제 준비 비교의 범위

설치된 0.1.1705와 계측 없는 수정 워커로 검색 페이지와 VCM PFC 페이지를 각각 최초·재준비했다.
8회 모두 소스 의존성·메타데이터 지문·경로 문맥·감시 디렉터리·모든 CSS가 같았으며,
원본 쓰기 시도와 종료 후 남은 검증 자식 프로세스는 없었다.

| 프로젝트 | 최초 준비 전→후 | 재준비 전→후 |
| -------- | --------------- | ------------ |
| 검색     | 7.33→6.06초     | 4.43→4.34초  |
| VCM PFC  | 5.97→5.29초     | 3.35→3.12초  |

이 표는 조건당 한 쌍의 측정이며 전체 준비 속도 향상을 확정하지 않는다. 검색의 기존
render-only 경고는 최초 9개로 같고 재준비는 1→2개로 표시 횟수가 달랐으나 새 메시지 종류는
없었다. VCM은 두 버전 모두 경고·오류가 없었다. 두 준비를 합친 워커와 자식 프로세스의
관측 최고 RSS는 검색 약 1,882→1,964MiB, VCM 약 1,794→1,785MiB다. 메모리 상한은 그대로다.
